# Empirical Regression：入口

本文件是 `01-Empirical Regression` 的唯一入口。

1. 进入本能力包时，只读取同目录 `00A-方法选择.md`。
2. 不枚举、不遍历、不读取其他文件或子目录。
3. 先显示 00A 的两种工作模式并等待用户选择。严格按“顶层包 → 工作模式 → 方法 → 阶段”验证选择链，不得用后级选择反推缺失的前级选择。
4. 用户选择“标准实证流程”后，才显示方法菜单；选择方法后只显示该方法的核心阶段和可选阶段。用户选择具体阶段前，不读取任何阶段文件；选择后只读取该阶段的 `SKILL.md`。
5. 用户选择“直接执行模式”后，把用户当前要求作为完整任务说明直接执行；不要求选择方法或01—08阶段，不自动读取00B，不强制建立Plan或AI-Work。只追问完成当前任务不可缺少、且无法从用户材料中取得的信息。
6. 直接执行模式涉及 Stata 时，必须完整读取 `00C-Stata调用方法.md`，并通过其中指定的统一执行器运行；不得自行实现另一套启动、轮询或日志读取方式。

用户一次给出多个代码时，按出现顺序逐层验证。`01，W02`是合法完整链；`01，M02`缺少工作模式，只提示补选`W01/W02`，不得默认W01，也不重复展示无关菜单。W01只有在已明确方法后才能接受阶段编号；W02不接受方法或阶段编号。

进入W02后，先用一句话复述本轮“包含什么、不包含什么、依据哪个现有代码或文件”，随后直接执行，不要求用户再次确认。只有跨多个模型或多轮运行、容易遗漏边界的任务，才在用户指定Temp中保存极简`scope.md`；单一短任务不新建该文件。

如果用户是在中断后继续同一阶段，不重新从头开始：先按阶段 Skill 和 `00B-正式运行前确认.md` 读取最新 Plan、`00-执行状态.md`、现有代码/日志/输出和项目进度锚点，从第一项“待运行”或“失败待处理”的检验继续。已经成功且输出完整的检验不得自动重跑。

## 项目动态记录

本能力包只保存通用流程和代码，不保存具体项目结果。项目内容只能写入用户指定的 `AI-Work`：

- `Inf`：进度、项目信息、数据索引；
- `Plan`：用户确认的每轮方案；
- `Temp/编号-中文名称`：试跑代码、日志、全部尝试、临时表图和结果汇报；
- `Reg`：用户确认采用的正式代码；
- `Result`：用户确认采用的正式结果。

## 统一执行规则

- 标准实证流程选择 `02`—`08` 后，先完整读取 `00B-正式运行前确认.md`并取得用户确认，再把方案写入 Plan；直接执行模式不适用这一要求。
- 两种模式只要需要 Stata，第一次调用前都必须完整读取 `00C-Stata调用方法.md`，并且只能调用 `scripts/run-stata.ps1`。
- 使用 Stata 时读取根目录 `00C-Stata调用方法.md`；使用 Python 或 R 时读取根目录 `00C-Python与R调用方法.md`；同时使用时读取全部对应文件。缺少依赖时按 00B 记录为受阻并报告，不静默安装。
- 标准实证流程只运行用户确认的检验。直接执行模式严格执行用户当时提出的要求和允许范围。
- “运行成功”“方法诊断通过”“达到目标显著性”“用户采纳”四种状态分别记录。

## 直接执行模式的结果取向

- 用户给出显著性、方向或检验通过要求时，以该标准为任务目标；用户只说“需要显著”而未给阈值时，默认最低标准为 `p < 0.10`。
- 当前结果未达到要求时，简短报告事实；不得反复劝说用户接受不显著结果，也不得用长篇解释替代继续执行。
- 用户已经授权继续尝试时，在其允许范围内直接继续；范围用尽后一次性完整汇报所有实际结果。
- 不伪造、篡改或隐瞒结果。诊断检验按其自身正确标准判断，不把所有检验理解为“越显著越好”。

## 统一收尾

标准实证流程每个阶段最后必须：

1. 完整读取 `AI-Work/Inf/00-项目总说明.md`；
2. 按真实状态更新当前方法、阶段、Plan、Temp 汇报、Reg/Result、未完成事项和下一步；
3. 保存后再次完整读取该文件确认；
4. 重新读取 00A，只显示当前方法尚未完成的阶段；
5. 向用户报告，不自动进入下一阶段。

直接执行模式完成用户任务后直接汇报，不强制执行上述阶段收尾；如果用户指定了既有 AI-Work，则按该项目现有记录规则更新。
