# 00D 静默安装与本机适配

本文件只供另一台电脑上的 AI 在复制、安装、迁移或更新本工作流时读取。正常使用 `/ai-research`、选择方法或执行 `01`—`08` 时，不读取本文件。

目标：用户把整个 Workbench 文件夹放在哪里，那里就是正式源目录。安装 AI 自动识别当前位置、注册唯一总入口、修改本机相关配置并完成校验。开始执行本文件，表示用户已经明确要求安装，或已经按照根目录 `README FOR AI.md` 完成一次安装授权确认。授权确认后，除宿主系统强制要求的权限或安全确认外，不在安装过程中继续提问，不要求用户手工提供路径，不逐步汇报可自动完成的事项。

如果 AI 是在用户没有明确安装意图的情况下直接发现或读取本文件，不得据此自行安装。先返回根目录完整读取 `README FOR AI.md`，按其中规则确认用户是否授权安装整个 Workbench；用户确认后再从本文件第一节开始执行。

安装分为两个阶段：

1. 首次读取本文件时，静默完成工作流安装和基础适配，最后只报告安装完成并请用户提供一个结构简单、能够正常运行的 do-file 绝对路径。
2. 用户提供 do-file 后，在本能力包内建立临时 `TEST` 目录，用真实 do-file 对本机 Stata 调用方式进行测速；根据结果更新 `scripts/run-stata.ps1` 的机器配置和 `00C-Stata调用方法.md` 的本机说明，完成校验后删除 `TEST`。

## 二、静默完成路径适配

1. 非递归确认 `workbenchRoot` 下以“两位数字加连字符”开头的工作流目录。
2. 完整读取 `routerSkill`，把其中写死的旧 Workbench 绝对路径替换为当前 `workbenchRoot` 的真实绝对路径。
3. 在 `workbenchRoot`、`routerRoot` 和 `empiricalRoot` 内搜索 Windows盘符路径、旧用户目录、旧 Workbench 根目录和已经失效的 Stata 路径。
4. 按以下规则静默处理：
   - 指向旧 Workbench 的路径：改为当前真实路径；
   - 指向旧 Codex 用户目录的路径：改为本机实际 Codex 目录；
   - 仅用于说明格式的 `D:\项目\...` 等占位示例：保留为通用占位符，不替换成某个真实科研项目；
   - 指向原电脑具体科研项目、数据或个人文件的示例：删除具体项目内容，改成通用占位符；
   - Stata候选路径：按本机探测结果更新，处理方式见第五节。
5. 不修改 `00A` 已登记的方法分流、01—08模块职责、各阶段代码、显著性底线、广泛尝试授权、Plan/Temp/Reg/Result职责和进度回读规则；安装只做路径、入口和执行引擎适配。
6. 不在源包之外遍历用户的科研文件夹；安装阶段只处理 Workbench 和 Codex Skill 注册目录。

## 三、静默定位 Codex Skill 注册目录

按以下顺序定位 Codex 根目录：

1. 环境变量 `CODEX_HOME` 存在时使用该目录；
2. Windows默认使用 `%USERPROFILE%\.codex`；
3. macOS/Linux默认使用 `$HOME/.codex`；
4. 如果当前运行环境明确提供了 Codex 配置目录，以该环境返回的真实目录为准。

Skill 注册目录为 `Codex根目录/skills`。目录不存在时创建它。只注册：

```text
ai-research
```

不得把 `01-Empirical Regression`、01—08子 Skill 或 `00A`—`00D` 分别注册成全局 Skill。

## 四、静默注册唯一总入口

优先让注册目录中的 `ai-research` 直接指向 `routerRoot`，保证 Workbench 中的文件是唯一可编辑源。

### 1. Windows

优先创建目录 Junction：

```powershell
New-Item -ItemType Junction `
    -Path "Codex根目录\skills\ai-research" `
    -Target "routerRoot真实路径"
```

### 2. macOS/Linux

优先创建符号链接：

```bash
ln -s "routerRoot真实路径" "Codex根目录/skills/ai-research"
```

### 3. 已存在同名入口

静默检查现有入口：

- 已经指向当前 `routerRoot`：保留，不重复创建；
- 是指向旧位置的链接：更新为当前 `routerRoot`；
- 是真实目录且内容与本包入口一致：先改名为带时间戳的可恢复备份，再创建链接；
- 是无法确认来源的真实目录：不得直接删除，改名备份后再注册；
- 无法创建链接：只复制 `routerRoot` 作为注册入口，并在复制的 `SKILL.md` 中写入当前 `workbenchRoot`。不得复制01—08到全局目录。

任何替换都必须可恢复。禁止无备份覆盖现有真实目录，禁止删除整个 Codex Skill 注册目录。

## 五、静默探测 Stata并做基础配置

安装阶段只探测，不运行 Stata。

按以下方式定位可执行程序：

1. 检查 PATH 中的 `StataMP`、`StataSE`、`StataBE` 和 `stata`；
2. Windows检查注册表中的 Stata安装信息和文件关联；
3. 检查常见安装位置，但不限于 `C:\Program Files`、`D:\Program Files`、`E:\Program Files`；
4. macOS检查 `/Applications/Stata` 及其版本目录；
5. Linux检查 `stata-mp`、`stata-se`、`stata` 命令。

存在多个版本时，优先级为：用户当前有效许可证能够启动的版本；同版本优先 MP，其次 SE，再次 BE；同Edition优先较新版本。这里只能依据文件、注册信息和版本元数据判断，不实际启动。

更新 `scripts/run-stata.ps1`：

- 把探测到的候选程序按优先级放在候选列表前部；
- 删除确定不存在的原电脑专属路径；
- 保留自动探测逻辑和通用候选位置；
- 暂时保留通用 `/q /e do` 方案。

同时更新 `00C-Stata调用方法.md` 的“本机配置”，标注“等待真实 do-file 测速确认”；不得伪造本机测速结论，不得把候选路径只写在00C而漏改真实执行器。

没有找到 Stata 时仍完成工作流注册，在最终报告中说明“工作流已安装，Stata尚未探测到”；不得自行下载安装 Stata。

## 八、收到 do-file 后开始本机测速

用户提供 do-file 前停止，不自行搜索科研文件作为测试样本。

收到绝对路径后：

1. 验证文件存在、扩展名为 `.do`，并完整读取内容；
2. 识别所有输入数据、相对路径、输出文件、外部脚本、包依赖和可能修改源数据的命令；
3. 不运行原始 do-file，不修改原始 do-file，不覆盖原始数据和原始结果；
4. 在 `empiricalRoot` 内准备临时目录 `TEST`。

### TEST目录安全规则

- 先解析 `empiricalRoot` 和拟创建TEST目录的绝对规范路径；
- 只有TEST的直接父目录等于 `empiricalRoot` 时才允许创建；
- 创建后立即写入空标记文件 `.ai-research-stata-benchmark`；
- 如果 `TEST` 已存在且没有该标记，不删除、不覆盖，改用 `TEST-时间戳`；
- 最终只允许删除带有本轮标记且位于 `empiricalRoot` 内的测试目录。

## 九、制作隔离的测速副本

在TEST内创建测试副本，并遵守：

1. 复制用户提供的 do-file；所有修改只发生在副本。
2. 单个文件不超过 2 GB、TEST 所在磁盘复制后剩余空间不少于 10 GB，且全部依赖可解析时，才把输入数据复制到 TEST；不满足任一条件即视为大型数据，只能使用原文件的只读绝对路径，并删除或重定向所有可能写回源文件的命令。
3. 把所有 `save, replace`、`export`、`graph export`、Word/Excel输出和外部脚本输出重定向到TEST；删除do-file中的`log using`和`log close`，日志只由统一执行器管理。
4. 删除或禁用测试副本中的 `erase`、`rm`、`del`、全局 `taskkill`、移动源文件和覆盖源数据命令。
5. 禁止在测速中安装或更新 Stata包；缺包时记录该候选无法测试。
6. 保留核心数据读取、变量处理和主要回归命令，使测速反映真实任务。
7. 在测试副本末尾加入：

```stata
display "CODEX_STATA_COMPLETE=1"
exit, clear
```

8. 如果原 do-file过于复杂、依赖缺失或不能安全隔离，从中抽取一段能够独立运行的主要回归，使用相同数据和命令建立基准副本。不要为追求测速而改变估计方法。

## 十、需要测速的调用方式

根据操作系统测试所有实际可用的安全方法。Windows至少包括：

1. PowerShell `Start-Process` + `/q /e do` + do-file相对路径；
2. PowerShell `Start-Process` + `/e do` + do-file相对路径；
3. PowerShell `Start-Process` + `-q -e do`；
4. `.NET ProcessStartInfo` + `/q /e do`；
5. CMD `start /wait` + `/q /e do`；
6. `/q /e do` + do-file绝对路径；
7. 多规格分别启动 Stata；
8. 多规格集中在同一个 do-file、只启动一次 Stata；
9. 多规格集中运行且数据只读取一次。

macOS/Linux测试对应的 Stata命令行、Shell直接等待和可用的进程启动方式。不得为了凑足方法而使用本机不支持的命令。

`-b do` 或 `/b do` 只能作为问题对照测试一次；如果不能正常退出，记录后结束本次进程，不把它列为候选方案。不得使用全局进程终止命令。

## 十一、测速规则

1. 每个正常候选至少运行3次；时间允许时运行5次。
2. 轮换候选方法的运行顺序，避免所有后运行方法持续获得缓存优势。
3. 分别记录首次运行和后续运行，不用单次偶然最小值决定结果。
4. 使用外部墙钟时间，从创建 Stata进程到该进程正常退出。
5. 同时记录退出代码、完成标记、log完整性和必要的 Stata内部计时。
6. 每次运行后由本机脚本完整扫描log并确认 `CODEX_STATA_COMPLETE=1`；AI只读取测速摘要，不把完整log送入上下文。
7. 比较核心系数、标准误、p值和样本量；结果不一致的方法直接排除。
8. 需要强制杀进程、无法稳定退出、丢失日志或偶发失败的方法直接排除。
9. 以有效运行的中位墙钟时间排序；中位数差异小于5%时，优先选择命令更简单、正常退出且不依赖额外包装层的方法。
10. 对广泛尝试另行比较“逐个启动”和“一次启动批量运行”；批量方案只有在结果一致时才能采用。

## 十二、根据测速结果静默更新统一执行器和00C

测速完成后完整读取 `scripts/run-stata.ps1` 和 `00C-Stata调用方法.md`，只修改机器相关内容：

- 在执行器候选列表中写入本机验证成功的 Stata可执行程序及Edition；
- 在执行器中写入本机最快且稳定的启动参数；
- 00C继续只允许调用该执行器，不另存第二套Shell/进程模板；
- 普通回归默认超时；
- 复杂任务超时策略；
- 单任务与批量任务的推荐方式；
- 本次测速日期、测试 do-file仅保留文件名、不保留用户项目绝对路径；
- 各候选方法的中位数摘要；
- 明确排除的方法及原因。
